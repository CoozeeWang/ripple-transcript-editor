# 音频格式处理测试素材

验证两件事：解不了码的音频会明确报错，白名单外的格式不会出现在列表里。

## 怎么用

应用里点「选择音频所在文件夹…」，选中**本文件夹**。

## 期望结果

| 文件 | 期望发生什么 |
|---|---|
| `broken-audio.mp3` | **会出现**在音频列表里并被自动载入。因为内容是乱码，浏览器解码失败，界面顶部应出现红色提示：「浏览器无法播放「broken-audio.mp3」：这个格式它不支持，或文件已损坏。请转成 mp3 / wav / m4a / mp4 / mov / flac / ogg / opus / 3gp 中的一种再打开。」 |
| `ignored.wma` | **不应出现**在音频列表里 |
| `ignored.amr` | **不应出现**在音频列表里 |

## 为什么把 wma / amr 从白名单里去掉

列出来的格式必须同时满足三条，缺一条就是「能选但用不了」：

| | 浏览器能播 | ElevenLabs 能收 | 现实里常见 |
|---|---|---|---|
| mp3 wav m4a flac ogg | ✅ | ✅ | ✅ |
| mp4 mov m4b webm aac | ✅ | ✅ | ✅ |
| opus 3gp mkv m4v oga | ✅ | ✅ | △ |
| **wma** | ❌ Chrome/Safari 都不行 | ❌ 不在支持列表 | △ |
| **amr** | △ 仅部分浏览器 | ❌ 不在支持列表 | △ |
| m4p aiff aif | △ 仅 Safari | ✅ | ❌ |

wma / amr 以前能出现在列表里，但选了之后既播不出、也传不了转写，
而且 `<audio>` 没有错误处理，点了播放毫无反应 —— 是最难自查的一类问题。

## 备注

- 白名单在 `frontend/src/localStore.ts` 的 `AUDIO_EXT`，提示文案用的
  `AUDIO_EXT_LABEL` 也从同一处导出，改格式只需改一个地方。
