# 导入功能测试素材

用这个文件夹验证「导入已有转录（JSON）」的匹配引导、自动修复与错误提示。

## 怎么用

1. 应用里点「选择音频所在文件夹…」，选中**本文件夹**。
2. 打开文件夹会自动载入 `interview-A.wav`（30 秒，第一个音频）。
3. 顶栏「切换文件夹」菜单 → 「导入已有转录（JSON）…」，按下面顺序逐个选文件。
4. 每测完一个，命名框直接关掉即可；导入结果会写进本文件夹的
   `interview-A.transcript/` 或 `interview-B.transcript/` 目录，测完可整个删掉。

## 两个音频

| 文件 | 时长 | 用途 |
|---|---|---|
| `interview-A.wav` | 30 秒 | 自动匹配的目标 |
| `interview-B.wav` | 45 秒 | 时长不匹配的对照组 |

## 匹配与落盘

| 文件 | 期望发生什么 |
|---|---|
| `01-exact-match.json` | 音频名完全一致 → **直接导入，不弹窗**，挂在 `interview-A.wav` 下 |
| `02-stem-match.json` | 写的是 `interview-A.mp3`，实际是 `.wav` → 同主干名匹配，**直接导入** |
| `03-no-match-choose.json` | 写的是「别的录音.mp3」→ 弹**「这段转录属于哪个音频？」**，列出 A 和 B 供选择 |
| `04-duration-mismatch.json` | 名字精确对上 `interview-B.wav`（45 秒），但转录写到 60 分钟 → 弹**「转录和音频对不上」**警告，可选「仍要导入」或「重新选择」 |

## 自动修复：不再报错，直接补好

这些文件**能导入成功**，补了什么会写在导入后弹出的命名框里（「导入时自动处理了几处」）。

| 文件 | 缺什么 | 期望的提示 |
|---|---|---|
| `06-no-speakers.json` | 没有说话人名单 | 「文件里没有说话人名单，已按段落顺序自动建了 2 个」 |
| `09-unknown-speaker.json` | 第 2 段用了名单外的 `spk_9` | 「有 1 个段落用到的说话人不在名单里，已自动补上」 |
| `10-auto-repair.json` | 没写音频名、没写说话人名单、1 段缺 id、1 段缺文字、1 段没标说话人 | 先弹**音频选择器**（因为没写音频名），选完后命名框列出 4 条修复说明 |

## 仍然会拦下来的（无法自动补）

| 文件 | 期望的错误提示 |
|---|---|
| `05-not-json.json` | 「这个文件不是一份转录数据（打开后顶层不是一个对象）。任何工具导出的 .json 都可以，但顶层要是包含分段列表的对象。」 |
| `07-no-timestamps.json` | 「第 3 段没有时间码。本编辑器要靠时间码把文字和音频对齐……请用导出它的工具重新导出带时间码的版本。」 |
| `08-empty-segments.json` | 「这份转录里一段内容都没有，没有东西可导入。」 |

## 另一个单独测的场景

新建一个空文件夹，只放 `01-exact-match.json`（不放任何音频），再用应用打开它：
启动页应提示「此文件夹未找到音频文件（支持 .m4a / .mp3 / .wav 等）」。

## 备注

- `interview-A.wav` / `interview-B.wav` 是脚本生成的 8-bit 单声道低音量正弦波，
  只为提供准确的时长，播放时是连续低鸣，音量已经调得很小。
- 自动补出来的说话人默认叫「说话人 1 / 2 / 3」，可在左侧说话人卡片上改名或改派段落。
- 导入不挑来源：任何工具导出的 .json 都能用，只要含分段文字与时间戳；
  说话人缺失会自动补。
