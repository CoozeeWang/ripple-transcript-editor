# Desktop update checks

The installed app offers **Ripple → Check for Updates…** on macOS and **Help → Check for Updates…** on Windows. It opens a single update window, including from the welcome screen. The window checks only when opened or when the user retries. Ripple does not download a package, replace the app, install anything, quit or restart as part of this flow.

Ripple queries the published Releases of [the official repository](https://github.com/CoozeeWang/ripple-transcript-editor/releases) through GitHub's public API. Stable and `X.Y.Z-beta.N` versions are compared by semantic version; internal build numbers do not count. Drafts, unpublished releases and other prerelease types are ignored. The index lookup has a timeout, size limit and bounded pagination. A failure or an empty published index is never shown as “current.”

A newer release is offered only when it has a manual installer for the current platform: a Ripple DMG or ZIP on macOS, or a Ripple EXE on Windows. An updater-only `.app.tar.gz` asset does not qualify. The app shows the release body as plain text and opens the fixed official page for that release tag. If a newer release lacks an installer for the current platform, the window says so and offers the general official Releases page. The renderer cannot supply an arbitrary URL or installation path.

Choose the correct platform package on GitHub, save open work, then install it yourself. Keeping the same application identifier, installation location and application-data directory preserves local preferences, device credentials, MCP/tunnel/API settings and project references; installing a future version that changes a storage format requires its own migration review. A manually installed app will start new processes, so an active local MCP or tunnel connection may need to reconnect. External ChatGPT authorization, client registration and OS keychain prompts depend on those external systems and cannot be guaranteed by an app replacement.

The update check itself neither reads nor alters projects or stored credentials. The browser preview and development build do not perform an installed-app update check. Native menu appearance and manual installation must be checked on installed builds; source tests do not establish either result. Windows installer production and installed Windows acceptance remain deferred.
