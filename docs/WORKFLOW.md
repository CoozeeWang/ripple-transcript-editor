# Ripple 开发与仓库工作方式

这里是产品源码仓库；私人研究和内部验收不放在这里；真实音频、转录稿、项目、凭据和签名材料只留在本机。仓库远端和可见性由发布流程单独管理。

从可测试的 `main` 开一条围绕单一目标的功能或修复分支。开发过程中可以保留 checkpoint commit，提交信息说明当前状态。完成工作时，按功能检查暂存内容，把源码、必要测试和对应文档放在同一功能提交中；无关改动分开。不要把一轮对话当成一个提交，也不要把个人资料、缓存或构建产物提交进去。

提交前运行与改动相称的测试。前端测试、构建、lint、后端测试和 Ruff 是自动证据；浏览器检查、Mac/Windows 打包和已安装桌面版操作分别记录，不能互相替代。`main` 应保持可测试、可构建；未完成或已知损坏的工作留在功能分支。

通过审阅后合入 `main`。临时 checkpoint 没有独立价值时可以在合并前 squash；有独立功能、修复或验收价值的提交可以保留。不要为整齐而重写现有有价值的历史。未经明确授权，不改 remote、不 push、不改变仓库可见性、不 force push。
