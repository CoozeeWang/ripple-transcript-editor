# 新增文案与维护约定

- 新界面文字放在 `frontend/src/i18n/locales/zh-CN.json` 和 `en.json` 对应模块下，先保证中文回退，再写英文。调用 `msg()`；React 组件订阅 `useInterfaceLanguage()`。新条目优先取有语义的键名；本轮 m 编号对应首轮盘点，保留以便追溯。
- 写完整句并用命名占位符插入动态值，避免把英文语序锁死在中文拼接顺序中。不要以已翻译字符串作状态、ID、判断条件或存储键。旧提示状态只有在提示展示处使用 `uiMessage()`，绝不能对正文/名称调用它。
- 项目名、转录稿、批注、说话人、用户规则、模型 ID、AI 返回正文属于数据。内置规则通过 `builtinText()` 仅翻译显示，API 请求保持原文。现有默认版本名也是持久化名称，暂时保留，是否为新建数据采用英文需要单独产品决定。
- 日期保留用户输入精度，日期字段不擅自转换时区；英文相对时间使用 Intl.RelativeTimeFormat，长日期使用界面语言。时间码、字幕小数、文件名日期、序号保留机器兼容格式。中英文均使用阿拉伯数字；需要分组的普通数值可用 `formatNumber()`，序号和时间码不要分组。
- 快捷键通过 `keys()` 和 `IS_MAC`，不要硬写仅适用 Mac 的 Option/Command。系统文件窗口、权限窗口和打印面板不受界面语言控制。
- 新后端异常应有稳定错误码及参数。兼容旧版 detail 的目录在 `backend/app/error_catalog.json`；新增条目要同步资源、错误映射测试与人工检查表。参数不得包含密钥或转录正文；未知异常用通用可读说明，具体诊断按现有脱敏规则记录。
- 修改英文后复核对应场景；历史审阅表和用户意见保存在私人工作空间，不从审阅快照自动写回翻译资源。

检查：仓库根目录运行 `node scripts/i18n-audit.mjs`；前端测试、构建与 lint；涉及后端时运行后端测试与 Ruff；涉及启动器时运行 `node --test scripts/*.test.mjs`。审计脚本校验资源参数、调用键以及中文残留登记，不能证明所有动态英文语法、布局或原生流程已验收。

每批记录：覆盖场景、自动检查结果、真实窗口观察、未验收项。不要把浏览器测试或构建成功称作独立 Ripple 应用验收。
