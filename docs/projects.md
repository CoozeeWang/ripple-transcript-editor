# Ripple 本地项目

项目是包含多次访谈的工作集合。项目首页可以新建、打开、修改名称与说明、添加访谈和多段录音、另存完整项目。全局引擎与偏好设置继续独立保存。

## 使用方式

1. 新建项目，先填写项目名称，点击“选择位置并保存项目”，选择父文件夹；成功写入并核对 `<名称>.ripple` 后进入项目页。取消选择或保存失败时保留名称，不显示场次或材料导入区；同名项目不覆盖。
2. 在已保存的项目里点击“新增场次”，填写场次名称后确认，再导入音频或转录稿。项目说明可在项目页填写。音频导入时选择复制／引用方式。
3. 使用批量材料整理时，在确认清单中修改访谈名称和音频对应关系。相同访谈名称归入一组；文件夹导入默认按所在目录分组，同名音频与稿件只作为关联建议。允许稿件保持待关联。
4. 支持常用音频及 Word（.docx）、TXT、SRT、VTT、JSON。Word 仅导入正文，不保留排版、批注和修订历史；旧 .doc 通过本地 Word 读取适配器转换，在当前 Mac 使用系统 textutil，读取失败可用 Word 另存为 .docx 后导入，Windows 原生支持仍待验。TXT、Word 无时间戳稿件可编辑，不虚构音频时间，后续可关联音频，关联文件不等于自动对齐文字。
5. 音频默认复制，也可引用。外部导入稿件直接可编辑，不另建只读副本；用户设为“原始转录稿”时，现有稿件变为只读。源文件不改动。一次访谈可有多份音频和待关联稿件，每份保持独立版本及时间轴。
6. 导入分批准备文件，最终一次更新项目索引；失败时清单保留供重试，磁盘可能保留未发布的暂存目录，不覆盖已有内容。
7. 返回访谈前先完成稿件保存。外部录音失联或内容变化时，已有稿件仍可打开；“重新关联”只接受内容一致的原录音。尚无音频的稿件使用“关联音频”选择文件。
8. 项目页的导出按钮打开材料／项目副本导出窗口；项目副本保留场次、稿件版本及项目内音频。引用的外部音频仅保留引用说明，回收站不包含在副本中；没有场次时隐藏导出入口。详见[保存与导出](SAVING_AND_EXPORT.md)。

旧文件夹和旧 Ripple 稿件迁移保留为次级入口；录音卡片“更多”中可找到旧稿件导入，不出现在新建项目的名称与保存步骤中。

## 磁盘结构与边界

`.ripple` 当前是普通文件夹，不是压缩包，也还不是 macOS 注册的文档包。

- `ripple-project.json`：项目名称、说明、访谈元数据、录音清单及稳定编号。
- `ripple-project.json.bak`：上次写入前经过校验的索引。损坏时不会静默回退，避免隐藏新增内容；目前没有备份恢复界面。
- `interviews/<访谈编号>/media/`：项目内音频副本。
- 同一访谈目录下 `<录音编号>.transcript/`：已有稿件版本格式；每段录音独立。

名称与磁盘编号分离，改名不移动或重命名音频。音频内容采用分块 SHA-256 覆盖全文件进行校验。复制和重新关联都进行内容检查。

项目页在音频名称下显示 `HH:MM:SS` 格式的时长；尚未打开或播放器尚未确认时显示 `--:--:--`。打开音频后，播放器接受的时长按该音频的内容指纹保存到项目，后续修正继续更新，返回项目页和重开项目均可读取。时长不依赖转录稿或版本；缓存不是独立文件扫描结果。内容指纹不符或检测到文件内容改变时不显示旧值，保存失败会提示重开音频重试。

引用外部文件的访问句柄和最近项目记录存于当前浏览器的 IndexedDB。清理浏览器数据、换浏览器或换电脑后可能需要重新关联。稿件和项目索引保存在磁盘，不依赖这些浏览器记录。项目副本中的稿件和项目内音频不依赖原设备句柄；引用的外部音频只保留说明，重新打开副本后仍需定位原文件才能恢复播放。

桌面版会保存用户明确选择过的文件／文件夹授权，重启时先校验资源身份再恢复；不是每次重启都要求重新选择。旧版未保存、已失效或资源被替换的授权，仍需通过系统文件窗口重新选择；重新打开最近项目时会核对项目编号。项目内复制的音频若一时无法读取，应先检查项目访问，不要直接当作外部原文件失联。Windows 原生授权恢复仍保留 Release 前实机待验标记。

索引写入带版本冲突检查及校验；支持 Web Locks 时，同源浏览器窗口间拒绝同时编辑同一项目，完整复制也会取得编辑锁。这不是跨浏览器、跨设备或同步盘的协作锁。不要同时在其他软件中修改项目内部文件。

项目副本先标记 `COPY-INCOMPLETE.txt`，全部成功后才发布项目索引。失败副本保留，原项目不变。加入录音失败也可能留下未被索引引用的副本，不自动清理以避免误删。多段录音目前不自动拼接为一个连续时间轴。

稿件索引的读取在编辑器和项目管理中使用同一恢复规则：正式索引有效时优先使用，否则验证备份及其引用的稿件文件。恢复读取不改写原件，权限错误不会通过备份绕过。项目副本保留稿件的 AI 规则和任务日志；未完成任务保持暂停，目标项目身份随副本更新，版本 ID 保留。损坏的单个任务日志单独提示并保留原件，其他通过校验的任务仍可使用。

## 验证

项目存储测试使用模拟文件系统验证复制、引用、多录音隔离、改名、版本冲突、错误重关联、全文件校验、失联稿件读取与搜索、项目副本及失败副本、索引损坏与写入失败恢复。编辑器既有回归测试同时运行。

项目首页和表单已有浏览器／组件证据；Mac b83 已获使用者安装版验收通过。这不代表每种目录权限或跨设备搬迁均已验证。Windows 安装包、原生目录选择／授权恢复及实机验收仍留到 Release 前；不能将模拟文件系统测试当作对应平台已通过。

## 完整导入已有稿件

目前支持 schemaVersion 2 的 .transcript 稿件目录，需选择同时包含原音频和稿件目录的父文件夹。导入前校验所有清单引用文件、版本编号与对照关系，核对全音频内容及旧稿件记录的音频指纹。完整复制至新目录后，最后发布项目索引中的 manuscriptDirectory；失败时暂存副本不成为活动稿件。原稿文件内容、各编辑版本、引擎名、版本标签与活动版本保持不变。已有项目访谈资料优先，旧资料补入空项，旧版完整元数据仍在复制的稿件中。

已有稿件的目标录音暂不支持合并导入，操作会明确拒绝覆盖。可以另加同一录音后导入。损坏或旧格式稿件会提示处理，不会修改来源。完整项目归档会保留导入目录映射。

## 导入来源与无时间戳数据

模型增加 sourceKind（import/transcription）及 sourceName。普通导入只存一份可编辑稿；指定原始转录稿时直接标记现有稿件，不复制。导入时已指定原稿的，只存一份只读稿。取消标记后沿用同一文件编辑。历史 original 指针继续兼容，不自动删除已有底稿。已有无 sourceKind 的引擎记录继续按原规则读取。

只有稿件的项目条目 storage 为 none，仍使用稳定编号存储版本；不会写入假音频文件。timeAligned=false 表示没有时间戳，内部数值占位不展示、不导出成真实时间，不从文字位置跳转音频。实际关联音频以后依然不自动生成对齐关系。无时间戳稿件可以由 MCP 在当前访谈中读取和分析；拆分段落不改变时间戳缺失的边界。

解析测试覆盖 Word 正文、TXT、SRT/VTT 时间戳及分组建议；存储测试覆盖单份导入及原稿标记、无音频稿件打开/归档/关联音频、批量分组及发布失败保护。界面测试覆盖新建项目先保存、保存失败保留名称、保存后创建场次、确认关联后才导入、失败后保留选择。真实系统文件选择和用户材料兼容性仍需桌面验收。

### 音频优先的材料整理

- 导入页先列音频，后列未关联稿件；同名只建议，不自动确认。每段音频选择访谈和稿件，确认后稿件移入音频条目，解除或移除音频会返回未关联列表。
- 多段音频可统一设置访谈。已存在的唯一同名访谈会接收材料，不再重复新建；同名访谈有歧义时要求从目标访谈中加入。
- 音频可试听，稿件可展开预览。读取到音频时长后，稿件时间戳超出时长会提示核对，不自动拒绝部分稿件或组合稿件。没有时间戳不等于关联错误，也不会自动补造时间戳。
- 完整稿件对应多段音频时可作为访谈中的独立稿件保留。
- 访谈材料的“更多 → 调整稿件关联”支持将完整版本历史移到同访谈的其他音频，或解除为独立稿件。目标已有稿件时拒绝覆盖。复制校验后发布新目录指针，旧目录保留；版本内容与时间戳不改动，不调用 AI。

### 直接选择关联转录稿

音频条目通过“关联转录稿”打开系统文件选择器，支持单选、多选，不提供已加入材料的快捷候选。已扫描的同一文件按文件句柄识别并移入音频下方，避免重复导入；已关联其他音频时要求先解除。每份转录稿创建独立 model，直接保存独立可编辑版本；用户指定原稿后该稿件变为只读。版本菜单的转录稿标题旁可改名，源文件名仍保留在 sourceName。

“忽略”使用圆圈减号，仅排除本次导入；忽略音频会把其转录稿退回未关联列表。场次使用日历、音频使用麦克风、转录稿使用文档图标，并以缩进和分区表达从属关系。

## 场次整理流程

新建项目先填写名称并选择保存位置，成功保存后进入正式项目页。此时才可创建有名称的访谈场次，再从 Finder 或 Windows 文件资源管理器将音频拖入场次、将多份转录稿拖入某段音频，或拖入独立文稿区。场次日期、地点、人物及备注可留空。双击名称或元信息原地修改，支持键盘 Enter 编辑、Escape 取消。

场次、音频、同一音频下的转录稿和独立文稿分别排序。场次行获得键盘焦点后，按上/下键切换选中的场次；拖动手柄或 Option + 上下键只改变顺序，不改变关联。忽略音频保留关联文稿为独立文稿；可撤销，不删除磁盘原文件。

从条目右侧的点状手柄拖动排序，插入线表示新位置；场次和音频列表的空隙、末尾以及音频卡片内的稿件导入框上方均可释放。内部排序表示移动，外部文件进入有效导入区才表示复制；排序不复制或改写音频、转录稿内容。Windows 的键盘排序使用 Alt + 上下键。

新增场次确认后即保存到项目，导入的音频也立即成为正式材料，具有改名、删除和打开编辑的控件。保存失败不提前展示成功结果。加入材料时选择音频复制/引用方式；不能直接持久引用的拖放文件仍可重新选择原文件，核对一致后再引用。已有项目的批量材料整理保留“加入项目”确认步骤，导入失败保留整理状态供重试。给已有音频追加转录稿时先复制其完整历史到暂存目录，全部成功后切换项目索引，不原地覆盖已有历史。

新导入的可编辑稿件以完整原文件名（含扩展名）作为名称和初始版本名，独立稿件和关联音频的导入稿一致；不再统一显示为“修改稿 v1”。显式指定的版本名和副本名称优先保留。已有稿件不会批量改名。转录稿初次创建时取场次日期和地点，之后独立保存；编辑转录稿名称不会重命名场次或项目音频。原主题标签数据仍保留，编辑页显示备注入口。原稿模式的备注保存到清单，不改原稿正文。

验收边界：组件和内存文件系统测试覆盖拖放解析、排序关联、忽略撤销、失败重试、追加原版本保全及元信息独立；浏览器核对真实页面布局。Finder 到实际 Ripple 窗口的拖放、系统目录权限及真实音频预听仍需在用户环境验收。

对照版本默认使用编辑版本记录的比较来源（如 AI 编辑前的版本）；没有明确来源时，优先选择同一录音下标记的原始转录稿，再回退到当前文稿的只读底稿。手动选择的对照版本在当前编辑会话内保留。

## 拖入音频后引用原文件

拖放如果提供可长期保存的文件句柄，可直接选择引用。Mac 桌面当前通过 HTML 拖放接收文件内容；这类临时文件不能直接保留引用。音频存放方式弹窗明确说明此限制；用户点选“引用原文件”时直接打开文件选择窗口，重新选定拖入的全部音频。程序核对完整内容、保留拖入顺序，再使用选择窗口获得的文件关联。确认成功后，“引用原文件”才被选中；点击“加入音频”完成导入。取消选择保持原存放方式和弹窗；数量或内容不符则提示且不导入。没有文件选择能力时显示取消后用虚线框选择文件的路径。音频的选择与导入不调用转录服务。

## 同项目移动录音到其他场次

在录音标题右侧、回收站图标左侧选择“移动到其他场次”图标；悬停可查看说明。也可先选择多条录音，再使用批量移动入口。选择同项目的目标场次并确认，录音的原始转录稿、编辑版本及批注一起移动。录音和稿件原有的日期、地点、参与人及备注保留，不用目标场次资料覆盖；外部音频引用也保留。本功能不把多个录音合成为一条时间轴。

## 删除与恢复整个场次

项目页品牌栏中，设置按钮左侧的回收站入口管理已删除材料。在当前场次名称右侧点击较小的回收站按钮，确认后将整个场次移入项目回收站。按钮与项目导出按钮的右边缘对齐。

场次名称、日期、地点、参与者、备注及其音频、转录稿、全部版本和批注作为一组保留。删除和恢复不改写音频或稿件文件，引用的外部原文件不受影响；外部音频暂时离线也不妨碍恢复场次。回收站中的场次条目提供整场恢复，原有顺序与材料关联随之恢复。短时“撤销”关闭或消失后，仍可从回收站恢复。

如果某份材料在删除场次之前就已进入回收站，恢复场次后它仍保持删除状态，可再单独恢复。删除最后一个场次后项目仍保留，也仍可打开回收站。AI 正在编辑的场次材料受到保护，须先完成或结束对应任务。永久清空回收站会移除整场恢复记录及项目内相关文件，需单独确认；它不会删除引用的外部原音频。导出的项目副本不包含已删除场次或其他回收站材料。
