# Ripple 本地项目

项目是包含多次访谈的工作集合。项目首页可以新建、打开、修改名称与说明、添加访谈和多段录音、另存完整项目。全局引擎与偏好设置继续独立保存。

## 使用方式

1. 新建项目，填写名称、可选说明，再选择保存位置。生成 `<名称>.ripple` 文件夹。
2. 创建完成后进入“加入已有材料”，支持选择多个文件或整个文件夹，也可跳过。已有项目沿用相同入口。
3. 在确认清单中修改访谈名称和音频对应关系。相同访谈名称归入一组；文件夹导入默认按所在目录分组，同名音频与稿件只作为关联建议。允许稿件保持待关联。
4. 支持常用音频及 Word（.docx）、TXT、SRT、VTT、JSON。Word 仅导入正文，不保留排版、批注和修订历史；不支持旧 .doc。TXT、Word 无时间戳稿件可编辑，不虚构音频时间，后续可关联音频，关联文件不等于自动对齐文字。
5. 音频默认复制，也可引用。外部导入稿件保留只读“导入稿”基准，并创建可编辑版本；只有 Ripple 调用转录引擎生成的才是“原始转录稿”。源文件不改动。一次访谈可有多份音频和待关联稿件，每份保持独立版本及时间轴。
6. 导入分批准备文件，最终一次更新项目索引；失败时清单保留供重试，磁盘可能保留未发布的暂存目录，不覆盖已有内容。
7. 返回访谈前先完成稿件保存。外部录音失联或内容变化时，已有稿件仍可打开；“重新关联”只接受内容一致的原录音。尚无音频的稿件使用“关联音频”选择文件。
8. 项目名称右侧“⋯”中的“导出完整项目副本”收集所有音频、稿件及版本；空项目隐藏此操作。

旧文件夹和旧 Ripple 稿件迁移保留为次级入口；录音卡片“更多”中可找到旧稿件导入，不出现在新建项目的材料引导中。

## 磁盘结构与边界

`.ripple` 当前是普通文件夹，不是压缩包，也还不是 macOS 注册的文档包。

- `ripple-project.json`：项目名称、说明、访谈元数据、录音清单及稳定编号。
- `ripple-project.json.bak`：上次写入前经过校验的索引。损坏时不会静默回退，避免隐藏新增内容；目前没有备份恢复界面。
- `interviews/<访谈编号>/media/`：项目内音频副本。
- 同一访谈目录下 `<录音编号>.transcript/`：已有稿件版本格式；每段录音独立。

名称与磁盘编号分离，改名不移动或重命名音频。音频内容采用分块 SHA-256 覆盖全文件进行校验。复制和重新关联都进行内容检查。

引用外部文件的访问句柄和最近项目记录存于当前浏览器的 IndexedDB。清理浏览器数据、换浏览器或换电脑后可能需要重新关联。稿件和项目索引保存在磁盘，不依赖这些浏览器记录。完整项目副本不依赖外部音频句柄。

索引写入带版本冲突检查及校验；支持 Web Locks 时，同源浏览器窗口间拒绝同时编辑同一项目，完整复制也会取得编辑锁。这不是跨浏览器、跨设备或同步盘的协作锁。不要同时在其他软件中修改项目内部文件。

完整复制先标记 `COPY-INCOMPLETE.txt`，全部成功后才发布项目索引。失败副本保留，原项目不变。加入录音失败也可能留下未被索引引用的副本，不自动清理以避免误删。多段录音目前不自动拼接为一个连续时间轴。

## 验证

项目存储测试使用模拟文件系统验证复制、引用、多录音隔离、改名、版本冲突、错误重关联、全文件校验、失联稿件读取与搜索、完整复制及失败副本、索引损坏与写入失败恢复。编辑器既有回归测试同时运行。

浏览器检查已覆盖项目首页与新建表单。系统目录选择对话框在当前自动化工具中不可操作，因此真实目录选择、持久授权、跨设备搬迁仍需桌面验收；不能将模拟文件系统测试视为这些步骤已经通过。

## 完整导入已有稿件

目前支持 schemaVersion 2 的 .transcript 稿件目录，需选择同时包含原音频和稿件目录的父文件夹。导入前校验所有清单引用文件、版本编号与对照关系，核对全音频内容及旧稿件记录的音频指纹。完整复制至新目录后，最后发布项目索引中的 manuscriptDirectory；失败时暂存副本不成为活动稿件。原稿文件内容、各编辑版本、引擎名、版本标签与活动版本保持不变。已有项目访谈资料优先，旧资料补入空项，旧版完整元数据仍在复制的稿件中。

已有稿件的目标录音暂不支持合并导入，操作会明确拒绝覆盖。可以另加同一录音后导入。损坏或旧格式稿件会提示处理，不会修改来源。完整项目归档会保留导入目录映射。

## 导入来源与无时间戳数据

模型增加 sourceKind（import/transcription）及 sourceName。为兼容已有版本存储，只读基准仍使用 original 指针，但导入稿的文件种类为 te-imported，名称及界面均使用“导入稿”。已有无 sourceKind 的引擎记录继续按原规则读取。

只有稿件的项目条目 storage 为 none，仍使用稳定编号存储版本；不会写入假音频文件。timeAligned=false 表示没有时间戳，内部数值占位不展示、不导出成真实时间，不从文字位置跳转音频。实际关联音频以后依然不自动生成对齐关系。无时间戳稿件可按完整段落提取 AI 编辑示范；拆分段落暂不用于学习示范。

解析测试覆盖 Word 正文、TXT、SRT/VTT 时间戳及分组建议；存储测试覆盖只读导入底稿、无音频稿件打开/归档/关联音频、批量分组及发布失败保护。界面测试覆盖新建后进入材料引导、确认关联后才导入、失败后保留选择。真实系统文件选择和用户材料兼容性仍需桌面验收。

### 音频优先的材料整理

- 导入页先列音频，后列未关联稿件；同名只建议，不自动确认。每段音频选择访谈和稿件，确认后稿件移入音频条目，解除或移除音频会返回未关联列表。
- 多段音频可统一设置访谈。已存在的唯一同名访谈会接收材料，不再重复新建；同名访谈有歧义时要求从目标访谈中加入。
- 音频可试听，稿件可展开预览。读取到音频时长后，稿件时间戳超出时长会提示核对，不自动拒绝部分稿件或组合稿件。没有时间戳不等于关联错误，也不会自动补造时间戳。
- 完整稿件对应多段音频时可作为访谈中的独立稿件保留。
- 访谈材料的“更多 → 调整稿件关联”支持将完整版本历史移到同访谈的其他音频，或解除为独立稿件。目标已有稿件时拒绝覆盖。复制校验后发布新目录指针，旧目录保留；版本内容与时间戳不改动，不调用 AI。

### 直接选择关联转录稿

音频条目通过“关联转录稿”打开系统文件选择器，支持单选、多选，不提供已加入材料的快捷候选。已扫描的同一文件按文件句柄识别并移入音频下方，避免重复导入；已关联其他音频时要求先解除。每份转录稿创建独立 model，保留只读来源与独立编辑版本。版本菜单的转录稿标题旁可改名，源文件名仍保留在 sourceName。

“忽略”使用圆圈减号，仅排除本次导入；忽略音频会把其转录稿退回未关联列表。场次使用日历、音频使用麦克风、转录稿使用文档图标，并以缩进和分区表达从属关系。

## 场次整理流程（2026-09-21）

新建项目先在内存中整理：填写项目名称，创建有名称的访谈场次，再从 Finder 将音频拖入场次、将多份转录稿拖入某段音频，或拖入独立文稿区。场次日期、地点、人物及备注可留空。双击名称或元信息原地修改，支持键盘 Enter 编辑、Escape 取消。

场次、音频、同一音频下的转录稿和独立文稿分别排序。拖动手柄或 Option + 上下键只改变顺序，不改变关联。忽略音频保留关联文稿为独立文稿；可撤销，不删除磁盘原文件。

最后一步选择保存位置与音频复制/引用方式。若拖放环境仅提供 File、无法提供可持久化文件句柄，则仅允许复制。选择位置不立即写文件；完成时写入项目，失败保留整理状态供重试。给已有音频追加转录稿时先复制其完整历史到暂存目录，全部成功后切换项目索引，不原地覆盖已有历史。

转录稿初次创建时取场次日期和地点，之后独立保存；编辑转录稿名称不会重命名场次或项目音频。原主题标签数据仍保留，编辑页显示备注入口。原稿模式的备注保存到清单，不改原稿正文。

验收边界：组件和内存文件系统测试覆盖拖放解析、排序关联、忽略撤销、失败重试、追加原版本保全及元信息独立；浏览器核对真实页面布局。Finder 到实际 Ripple 窗口的拖放、系统目录权限及真实音频预听仍需在用户环境验收。
